# paper/

The manuscript and its submission kit. The rule here is the same as everywhere else in this
repository: **no number is typed by hand.**

```
manuscript.md          the content of record — prose plus markers, no literal numbers
supplementary.md       supplementary methods, tables S1-S4 and Figure S1
build_manuscript.py    resolves the markers from results/ into build/manuscript.md
build/manuscript.md    the built manuscript (committed, so a reviewer can read it directly)
build_pdf.py           renders build/manuscript.md + Tables 1-2 + Figures 1-8 to a PDF
build_docx.py          renders the same content to an editable .docx (needs pandoc via pypandoc)
build/manuscript.pdf   the submission PDF (a derivative; not committed)
make_figures.py        draws Figures 1-8 from results/ into figures/
redlamp_console.py     re-measures the console record (results/redlamp_console.json), its
                       tiles, and the interactive HTML page
figures/               the figures, regenerated by those scripts
figures/console/       the console's unprocessed and processed tiles, read by Figure 8
figures/redlamp_console.html   the interactive console; a repository artefact, not Figure 8
```

## Building

```bash
python -c "from denoiq_core.experiment import run_all; run_all()"   # results/
python paper/make_figures.py                                        # paper/figures/ (Figs 1-8)
python paper/redlamp_console.py                                     # console record alone (needs [dl])
python paper/build_manuscript.py                                    # both documents' markdown
python paper/build_manuscript.py --check                            # fails if a build is stale
python paper/build_pdf.py                                           # paper/build/manuscript.pdf
python paper/build_pdf.py --document supplementary                  # paper/build/supplementary.pdf
python paper/build_pdf.py --submission                              # refuses until the DOI is minted
python paper/build_pdf.py --no-line-numbers --submission           # same, without line numbers
python paper/build_pdf.py --style preprint                          # the working single-column setting
python paper/build_docx.py                                          # paper/build/manuscript_v2.docx (needs pandoc)
python paper/build_docx.py --document supplementary                 # paper/build/supplementary_v2.docx
```

Figures are placed **immediately after the paragraph that first cites them** (SPIE JMI, single
column, near first mention) rather than collected at the end; a figure the prose never cites is
gathered into a trailing `Figures` block, which is the signal that a citation was lost. The
submission line numbers are the manuscript's alone — the supplementary material is not
line-numbered, since SPIE numbers the reviewed manuscript and its tables and methods are cited by
their own labels.

## The PDF

`build_pdf.py` needs the `[pdf]` extra (`pip install -e ".[pdf]"`, i.e. reportlab); it uses the
faces bundled inside matplotlib, so the Unicode in the manuscript (`‖ ₂ ² ′ σ ∝ √ Δ`) renders
rather than turning into boxes, and the output is byte-identical between runs.

Two settings are available. `--style jmi` (the default) is the SPIE *Journal of Medical Imaging*
submission setting: STIXGeneral, which is metric-compatible with Times, at 12 pt on a wide
leading, superscript citations, `Fig. N` references, SPIE section numbering, page numbers, table
captions above their tables, and the Disclosures / Code and Data Availability / Acknowledgments
back matter. `--style preprint` is the working single-column setting with a sans-serif heading
face. Times-metric faces do not carry every code point the text uses, so the JMI setting turns
Unicode exponents into real superscript runs and `tests/test_jmi_style.py` checks that every
character reaching the page exists in the font.

`--submission` refuses to build until `paper/release.json` carries the archived release's version
DOI; see `docs/RELEASE.md`. That is what keeps a placeholder out of a submitted PDF. It also turns
on continuous line numbers in the left margin — one per line of running text, from the first page
to the last, so a reviewer can cite "line 214" — which `--no-line-numbers` suppresses and
`--line-numbers` forces on a non-submission build. Figures, tables and their captions are not
numbered: a caption is cited by its own number, and numbering inside one would put the body count
out of step with the text it indexes. It is
**not** part of CI: a PDF is a derivative, and requiring a TeX or pango/cairo stack for one is
not a trade this repository makes. If pandoc and a LaTeX engine are installed, `pandoc
paper/build/manuscript.md -o manuscript.pdf` is an equivalent route.

The PDF is regenerated from `build/manuscript.md`, `results/` and `figures/` every time, and is
not committed — the built Markdown is the readable record in git. Corrections therefore never
reach a state that cannot be rolled back:

1. Read the PDF, mark it up.
2. Put the corrections in **`paper/manuscript.md`** — numbers as markers into `results/`, prose
   as prose. Anything inside a figure belongs to its generator (`denoiq_core/figures.py` or
   `redlamp_console.py`), not to the manuscript.
3. Re-run `build_manuscript.py` then `build_pdf.py`. `tests/test_manuscript_consistency.py`
   holds the line on "no typed numbers, build current, every marker resolves".
4. Typeset into the SPIE JMI template once, after the content is frozen.

Figure 8 is drawn by `denoiq_core.figures.figure8_console_panel` from
`results/redlamp_console.json` and the tiles in `figures/console/`, at journal text width and
deterministically — it is **not** a screenshot. `redlamp_console.py` produces that record, those
tiles, and additionally a self-contained `figures/redlamp_console.html`: the HTML is the
interactive artefact (and a good supplementary figure), while the manuscript figure is
regenerated from the record every time, so it cannot fall out of step with the measurements.
The console script needs the `[dl]` extra and a trained checkpoint; `--denoiser tv` runs it
without torch. `make_figures.py` refreshes the record when it can and otherwise draws Figure 8
from the existing one.

## How the numbers get in

Each quantity in `manuscript.md` is written as a marker naming a results file and a path
into it:

```
[[results:summary.json:max_excess_over_ceiling|.2e]]
[[results:dose_sweep.json:rows[mas=100.0,denoiser=raw].d_prime_ideal|.2f]]
[[results:task_gains.json:by_denoiser["TV(0.4 sd)"].mean_delta_d_prime_npwe|+.2f]]
```

`tests/test_manuscript_consistency.py` then enforces three things: every marker resolves,
the committed build matches a fresh render, and the prose contains no bare numbers outside
code spans, headings and the reference list. A result that changes and a sentence that does
not is a test failure rather than a reviewer's discovery.

## Submission

Target: **SPIE Journal of Medical Imaging**; fallbacks *Journal of Imaging*, *Medical
Physics*. Priority is established by the Zenodo DOI of the archived release, not by a
preprint server.

Checklist:

1. `pytest` green on the release commit; `results/` and `paper/build/` regenerated from it.
2. Tag and publish a GitHub release → Zenodo archives it and mints a **version DOI**.
3. Cite the **version DOI** in the manuscript ("the version used in this work"); the
   **concept DOI** goes in `README.md`, `CITATION.cff` and `.zenodo.json`.
4. Cite `taskiq-core` as the observer/task engine, by its own DOI.
5. Reformat `build/manuscript.md` into the journal's template; the content is unchanged by
   that step, and any number edited during it will fail the consistency test.
